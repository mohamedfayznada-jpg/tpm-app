# TPM Continuous Improvement Operating Model

## Purpose
The application is designed to manage a closed-loop TPM improvement process, not only audit completion.

## Core flow
Jishu Hozen / detection -> Abnormality -> TPM Tag -> Loss classification -> Root Cause Analysis -> Countermeasure -> Verification -> Standardization -> KPI impact.

## Required evidence
Every closure should be supported by appropriate evidence: problem statement, responsible owner, due date, RCA, countermeasure, verification result, and standardization evidence where applicable.

## Loss taxonomy
- Breakdown
- Minor Stop
- Speed Loss
- Defect
- Setup / Adjustment
- Waiting
- Material
- Other

## RCA methods
- 5 Why
- Fishbone
- Pareto
- A3

## Management principles
1. Detect abnormalities at the source.
2. Assign ownership and a due date.
3. Separate symptom correction from root-cause elimination.
4. Verify effectiveness before closure.
5. Standardize successful countermeasures.
6. Measure recurrence and business impact.
7. Use KPI trends to prioritize the next improvement cycle.

Plant-specific targets, scoring weights, escalation times, and role permissions must be configured from the approved factory standard; they are not assumed by this model.
